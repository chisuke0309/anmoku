# 設計書の評価（関門2）：agent-design_v2.md

**判定：条件つき合格**（重大0・中1・条件1・軽1）

評価に使った物差し：修正版の業務フロー（「仮」の行を含む。人の承認はまだ。承認したものとして評価した）と定義台帳。判定の規則は Python で固定（重大か中が1件でもあれば差し戻し、承認されていない定義に頼る部分が残るあいだは合格にしない）。

- [中]（観点A）設計書 処理手順 3. 見積「最終承認は店長が行う（公式フロー）。」
  - 問題：フローと台帳には「承認の無い見積は施主に提出しない」という決まりごとがある。設計書は最終承認者を案内するだけで、この決まりごとがどこにも書かれていない。承認前の見積を出してよいか聞かれたときの扱いが決まっていない。
  - 根拠：定義「見積の最終承認」＝承認済み
  - 合格の条件：「店長の最終承認が無い見積は施主に提出しない」と書かれ、承認前の提出を聞かれたら止めて店長の承認へ案内する、と決まっていること。
- [条件]（観点B）設計書 処理手順 3. 値引き 3. ／ 使う用語「値引きの基準」／ 確認待ち事項 #7「値引きの基準は確認待ちで、答えを持つのは店長。」
  - 問題：台帳の「値引き前の課長への相談と許容範囲」(未確定)は、答えを持つ人が工事統括の課長（佐藤さん）。設計書は値引きの基準の答えを持つ人を店長にしており、台帳と食い違う。未確定であることは明記され、エージェントは判断していない。直す点は確認先だけ。
  - 根拠：定義「値引き前の課長への相談と許容範囲」＝回答待ち／根拠 01_sales_junior.md:16「金額が一定より大きいのとか、値引きが入るやつは店長の承認が要るんです」 ほか5件
  - 合格の条件：値引きの許容範囲の確認先が台帳と合っている。または、店長を確認先にする理由が明記されていること。
- [軽]（観点A）設計書 処理手順 3. 値引き 2.「相談のあと、店長の値引きの承認と、見積の最終承認に回す（公式フロー）。」
  - 問題：台帳の決まりごとは「見積からの値引きは、金額にかかわらず店長の承認を得る」。設計書は承認に回すとだけ書き、金額にかかわらず必要な点が無い。少額の値引きなら承認は要らないのかと聞かれたときの答えが決まっていない。
  - 根拠：定義「値引きの承認」＝承認済み
  - 合格の条件：値引きは金額にかかわらず店長の承認が要る、と明記されていること。
