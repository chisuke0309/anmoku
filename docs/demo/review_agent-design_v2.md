# 設計書の評価（関門2）：agent-design_v2.md

**判定：条件つき合格**（重大0・中1・条件1・軽2）

評価に使った物差し：修正版の業務フロー（「仮」の行を含む。人の承認はまだ。承認したものとして評価した）と定義台帳。判定の規則は Python で固定（重大か中が1件でもあれば差し戻し、承認されていない定義に頼る部分が残るあいだは合格にしない）。

- [中]（観点A）設計書 処理手順 3. 見積「**見積**：営業担当が見積を作成する。最終承認は店長が行う（公式フロー）。」
  - 問題：フローの決まりごとの「現地調査は見積作成の前に必ず行う」が、見積の案内経路に書かれていない。現地調査をしていない見積についての問い合わせに、エージェントが何を案内するかが決まっていない。
  - 根拠：定義「現地調査」＝承認済み
  - 合格の条件：見積の経路に「見積作成の前に営業担当が現地調査（採寸・写真撮影・配管や下地の確認）を行う」を入れ、未実施の場合は先に現地調査をするよう案内すると書かれていること。
- [条件]（観点B）設計書 処理手順 3. 値引き 3「値引きの基準は確認待ちで、答えを持つのは店長。」
  - 問題：台帳では、値引きは金額にかかわらず店長の承認が要る（approved）。「値引きはまず聞く」の答えを持つ人は佐藤さんで、needs_answer。設計書は答えを持つ人を店長としており、台帳と食い違う。ただし、エージェントは判断せず人に回している。
  - 根拠：定義「値引きはまず聞く」＝回答待ち／根拠 01_sales_junior.md:32「「値引きはまず聞いときな」って言われたんで」 ほか1件
  - 合格の条件：値引きの基準を誰が決めるのかを台帳に合わせて整理すること。店長の承認（確定）と、佐藤さんへの事前相談（未確定）を分けて書くこと。
- [軽]（観点A）設計書 処理手順 3. 見積「最終承認は店長が行う（公式フロー）。」
  - 問題：台帳の「承認の無い見積は施主に提出しない」が書かれていない。店長の承認前に施主へ出してよいかと聞かれたときの扱いが決まっていない。
  - 根拠：定義「見積の最終承認」＝承認済み
  - 合格の条件：店長が見積システムで承認するまでは施主に提出しない、と案内に明記されていること。
- [軽]（観点A）設計書 処理手順 6. 不在のとき「代理者は確認待ち。代理者がいるかどうかは、店長に確認するよう伝える。」
  - 問題：不在の動きは決まっているが、不在なのが店長本人のときに「店長に確認する」と案内すると堂々巡りになる。店長が不在の間に、見積の最終承認や値引きの承認が止まる場合の連絡先が無い。
  - 根拠：フロー：見積の最終承認、値引きの承認（店長）
  - 合格の条件：店長が不在のときに代理者の有無を確認する相手（例：佐藤さんなど）が決まっているか、決まっていないことが確認待ちとして明記されていること。
