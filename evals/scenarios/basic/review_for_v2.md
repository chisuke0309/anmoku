# 設計書の評価（関門2）：agent-design_v1.md

**判定：差し戻し**（重大8・中1・条件1・軽0）

評価に使った物差し：人が承認した業務フロー（「仮」の行を含む）と定義台帳。判定の規則は Python で固定（重大か中が1件でもあれば差し戻し、承認されていない定義に頼る部分が残るあいだは合格にしない）。

- [重大]（観点A）設計書 処理手順 2（値引き）／エスカレーション「可否をエージェントは判断しない。店長の承認に回すよう案内する。」
  - 問題：フローでは、値引きが入るとき店長に上げる前に工事統括（佐藤さん・仮）へ相談し、返答待ちや差し戻しも起きる。設計書は佐藤さんの経路を扱わず、店長だけに回している。判断を人に回す点は慎重だが、相談の経路が抜けている。
  - 根拠：フロー：値引きが入る場合、店長に上げる前に相談する（仮）
  - 合格の条件：店長に上げる前の佐藤さんへの相談を手順に入れる。仮で未確認である旨と、返答待ち・差し戻しのときの動きも書く。
- [重大]（観点A）設計書 処理手順 2（職人の割当）「手配と工程表の作成は工務担当が行う。手配では優先客を先にすると回答する。」
  - 問題：フローでは、職人の割り振りを課長・佐藤さん（仮）が決め、それが出ないと工程表を出せない。優先客の指示も工務以外から出て、工務は事前に把握していない。設計書は、割り振りの経路も、優先指示が外から来て工程を組み直す流れも扱っていない。
  - 根拠：定義「付き合いのある・紹介のお客さんは優先して工程を回す」＝下書き／根拠 02_koumu.md:14「前から付き合いのあるお客さんとか、紹介で来たお客さんは、優先で回せって言われてる」 ほか1件
  - 合格の条件：割り振りは佐藤さん（仮）が決めると書く。優先客の指示を受けて組み直す流れも入れる。優先の範囲は未確定と明記し、一覧がないことを前提に確認先へ回す。
- [重大]（観点A）設計書 処理手順 2（見積・難あり物件の見積）「見積への上乗せを提案する。ただし上乗せ額は確定させない。」
  - 問題：フローでは、築年数が古い・状態が怪しい物件で、見積前に予備費の額を工事統括（佐藤さん・仮）に聞く。設計書はこの経路がなく、見積作成から店長の最終承認へ直行する。予備費の確認で見積が2〜3日延びる点も反映されていない。
  - 根拠：定義「予備費の金額」＝回答待ち／根拠 04_sales_senior.md:12「「じゃあ十五万見とこうか」とか言ってくれる」
  - 合格の条件：予備費の額は佐藤さん（仮）に確認する経路を入れる。上乗せの提案より前に、その確認が要ることを明記する。
- [重大]（観点A）設計書 処理手順 2（追加工事）「現場監督の判断で進めてよいと回答する。追加工事の見積は現場監督が作成する。」
  - 問題：フローでは追加工事を進める前に工事統括（佐藤さん・仮）へ確認する経路と、十万円超が見込まれるときは施主に言う前に一声かける決まりごと（仮）がある。設計書はどちらも扱わず、現場監督の判断だけで進めてよいと断定させている。決まりごとと逆のことをエージェントにさせる作りで、未確定事項4でも佐藤さんの確認と十万円ルールには触れていない。
  - 根拠：フロー：追加工事を進めてよいか確認する（仮）／十万円を超えそうな追加は施主に言う前に一声かける（仮）
  - 合格の条件：追加工事の確認先（佐藤さん・仮）と十万円超の事前連絡を設計書に入れる。「小さい追加」の範囲が未確定なら、その旨を明記し、断定せず佐藤さんへ回す。
- [重大]（観点B）設計書 処理手順 2（追加工事）「現場監督の判断で進めてよいと回答する。追加工事の見積は現場監督が作成する。」
  - 問題：「小さい追加」の範囲（small-addition-limit）と十万円超の事前連絡（notify-before-over-100k）はどちらも draft で、上限は本人も曖昧。設計書はこれを未確定と書かず、エージェントが「進めてよい」と当てはめている。
  - 根拠：定義「現場で決めて良い「小さい追加」の範囲」＝下書き／根拠 03_genba.md:30「小さい追加なら現場で決めていいって言われてるんです。」 ほか4件
  - 合格の条件：追加工事の可否は draft の定義に頼らない。未確定と明記し、佐藤さんへ回す作りにする。
- [重大]（観点D）テスト仕様 TC-03「現場監督の判断で進めてよいと回答する。追加工事の見積は現場監督が作成すると案内する。」
  - 問題：「進めてよい」は、台帳で draft の small-addition-limit と notify-before-over-100k に頼っている。金額の条件がないまま、現場判断でよいとする期待値は、正解が決まっていない。フローの佐藤さんへの確認も期待値にない。
  - 根拠：定義「現場で決めて良い「小さい追加」の範囲」＝下書き／根拠 03_genba.md:30「小さい追加なら現場で決めていいって言われてるんです。」 ほか4件
  - 合格の条件：金額や範囲の条件が決まるまで、期待値を「佐藤さん（仮）へ確認し、十万円超が見込まれるなら施主に伝える前に一声かける」とする。
- [重大]（観点D）テスト仕様 TC-04「優先客を先に手配すると回答する」
  - 問題：優先客の扱いは台帳で draft（priority-without-list、priority-customer-and-schedule）で、一覧がなく範囲は人の頭の中にある。「先に手配する」を期待値にするのは、正解が決まっていないテスト。佐藤さんの割り振りの経路も期待値にない。
  - 根拠：定義「付き合いのある・紹介のお客さんは優先して工程を回す」＝下書き／根拠 02_koumu.md:14「前から付き合いのあるお客さんとか、紹介で来たお客さんは、優先で回せって言われてる」 ほか1件
  - 合格の条件：優先客の扱いは未確定とし、佐藤さん（仮）の割り振りの確認と、優先の指示の有無を問い合わせ元に確認することを期待値にする。
- [重大]（観点D）テスト仕様 TC-07「15%の上乗せを提案する。上乗せ額は確定させず」
  - 問題：15%という数字は、台帳で未確定（contingency-amount、難あり物件）のもの。正解が決まっていないテストで、注意事項でも設計書と矛盾すると認めている。しかもフローでは、額は佐藤さん（仮）に聞くことになっている。
  - 根拠：定義「予備費の金額」＝回答待ち／根拠 04_sales_senior.md:12「「じゃあ十五万見とこうか」とか言ってくれる」
  - 合格の条件：15%を期待値から外す。「率は示さず、予備費の額は佐藤さんに確認し、店長の最終承認に回す」に差し替える。
- [中]（観点A）設計書 エスカレーション（承認者・回す先の不在時）「| 見積（上乗せを含む）の最終承認 | 店長 |」
  - 問題：店長（または佐藤さん・仮）が不在・返答待ちのときの動きが書かれていない。フローにも返答待ちで2〜3日延びる記載があるが、待つ・代理を立てる・期限を設けるといった扱いが決まっていない。
  - 根拠：フロー：返答待ちあり／差し戻しあり（フロー備考）
  - 合格の条件：承認者や相談先が不在のときの動きを決める。例：エージェントは代理承認せず、不在を伝え、戻り次第の連絡と代理者の確認を案内する。
- [条件]（観点B）設計書 エスカレーション表（未確定事項の窓口）「店長（暫定。正式な窓口は要確認）」
  - 問題：難あり物件・優先客・追加工事・予備費など未確定事項の答えを持つ人は、台帳では工事統括の課長（佐藤さん）。店長を窓口にすると、答えを持たない人に回すことになる。暫定と明記している点は良い。ただし、店長の判断が必要なもの（値引き基準など）と佐藤さんのものを分けていない。
  - 根拠：定義「難あり物件（難しい物件）」＝回答待ち／根拠 04_sales_senior.md:20「うちでは「難あり」って言ったりしますけど、何年以上とか決まってるわけじゃないですね。」 ほか2件
  - 合格の条件：未確定事項ごとに、答えを持つ人（佐藤さん／店長）を割り当てる。窓口が決まるまでの暫定の動きも書く。
